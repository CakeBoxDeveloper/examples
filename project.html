О проекте

Заказчик — компания, управляющая сетью из 340+ объектов по всей стране: подстанциями, узловыми пунктами и вспомогательными сооружениями. Задача — единая платформа мониторинга с возможностью быстрого доступа к паспорту каждого объекта, истории событий и статусу в реальном времени.

«Нам нужно было видеть всё на одном экране — от статуса оборудования до документов по каждой точке. Предыдущее решение требовало переключаться между пятью системами.»

— Дмитрий Г., технический директор заказчика

Архитектура

Фронтенд построен на React с использованием Mapbox GL JS для рендера карты. Вся бизнес-логика разделена на независимые модули: слой геоданных, слой событий и слой документов. Обновление в реальном времени реализовано через WebSocket с delta-синхронизацией — только изменённые объекты.

Стек подробно

  • React 18 + Zustand для стейт-менеджмента — минимальный bundle, предсказуемые обновления
  • Mapbox GL JS с кастомными слоями на WebGL — плавная работа с 10 000+ точек
  • PostGIS для геозапросов — пространственные индексы, radius-search за 3–8 мс
  • Fastify вместо Express — в 2.5× быстрее на нагрузочном тесте при тех же ресурсах
JavaScript 
// Подписка на реалтайм-обновления объектов
const ws = new WebSocket('wss://api.example.com/objects/stream');

ws.onmessage = (event) => {
  const delta = JSON.parse(event.data);
  store.applyDelta(delta); // обновляем только изменённые
  map.triggerRepaint();    // перерисовка только если нужно
};

ws.onclose = () => {
  setTimeout(() => reconnect(), 3000); // авто-реконнект
};

Сложности и решения

⚠️

Основная техническая сложность — рендер 10 000+ маркеров на карте без деградации FPS. Стандартный подход Mapbox с DOM-маркерами не подходил.

Вместо DOM-маркеров использовали кастомный WebGL-слой с инстансингом — все 10 000 точек рендерятся за один draw call. Кластеризация на стороне клиента через Supercluster с уровнями zoom 0–22.

  1. Инстанс-рендеринг на WebGL — x40 к производительности vs DOM
  2. Виртуальный скролл в боковой панели — список из 340 объектов без лагов
  3. Service Worker для кэша тайлов — карта работает офлайн при плохом сигнале
💡

Для быстрого radius-search в PostGIS достаточно добавить GIST-индекс по geometry-колонке — время запроса падает с 200 мс до 5 мс на таблице из 50 000 строк.

Результат

Платформа принята в эксплуатацию в марте 2024. Время на поиск нужного объекта сократилось с ~4 минут (переключение между системами) до 15 секунд. Команда из 12 диспетчеров работает в системе ежедневно.
